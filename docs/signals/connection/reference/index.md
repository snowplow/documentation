This page lists the interfaces, credentials, client options, and methods for connecting to Signals. To set up a connection step by step, see [Connect to Snowplow Signals](/docs/signals/connection/index.md).

## Parameters

Every interface except Console and the Snowplow MCP server uses the same connection credentials.

### Interfaces

This table shows which interface supports which task:

| Interface                                                       | Define configurations | Retrieve attributes | Subscribe to interventions |
| --------------------------------------------------------------- | --------------------- | ------------------- | -------------------------- |
| [Snowplow Console](https://console.snowplowanalytics.com)       | ✅                     | ❌                   | ❌                          |
| [Python SDK](#python-sdk)                                       | ✅                     | ✅                   | ✅                          |
| [Node.js SDK](#nodejs-sdk)                                      | ❌                     | ✅                   | ❌                          |
| [Browser plugin](/docs/signals/applications/subscribe/index.md) | ❌                     | ❌                   | ✅                          |
| [Signals API](#signals-api-endpoints)                           | ✅                     | ✅                   | ✅                          |
| [Signals MCP server](#signals-mcp-server-endpoint)              | ❌                     | ✅                   | ❌                          |
| [Snowplow MCP server](/docs/ai/snowplow-mcp/index.md)           | ✅                     | ✅                   | ❌                          |

Console uses your Console login. The Snowplow MCP server authenticates with your Console account or a Console API key.

### Connection credentials

The SDKs, browser plugin, Signals API, and Signals MCP server need four values. Add them to your environment secrets.

| Value           | Description                             | Where to get it                                                  | Format                                             |
| --------------- | --------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------- |
| Signals API URL | The API URL for your Signals deployment | Console > **Signals** > **Overview**                             | `https://{{123abc}}.signals.snowplowanalytics.com` |
| API key         | A Snowplow API key                      | [Generated by you](/docs/account-management/index.md) in Console | UUID                                               |
| API key ID      | A Snowplow API key ID                   | [Generated by you](/docs/account-management/index.md) in Console | UUID                                               |
| Organization ID | Your Snowplow organization ID           | Console > **Signals** > **Overview**                             | UUID                                               |

### Python SDK

Package: [`snowplow-signals`](https://pypi.org/project/snowplow-signals/) on PyPI. The `Signals` constructor takes the connection credentials:

<ParamTable>
  <Param name="api_url" type="str" required>
    The Signals API URL.
  </Param>
  <Param name="api_key" type="str" required>
    The Snowplow API key.
  </Param>
  <Param name="api_key_id" type="str" required>
    The Snowplow API key ID.
  </Param>
  <Param name="org_id" type="str" required>
    The Snowplow organization ID.
  </Param>
</ParamTable>

#### Python SDK methods

| Method                   | Description                                                                 |
| ------------------------ | --------------------------------------------------------------------------- |
| `publish`                | Registers the provided objects with Signals                                 |
| `unpublish`              | Unpublishes objects from Signals                                            |
| `delete`                 | Fully deletes objects from Signals (must unpublish first)                   |
| `test`                   | Tests an attribute group against the atomic events table                    |
| `get_service_attributes` | Retrieves attributes for a specific service from the Profiles Store         |
| `get_group_attributes`   | Retrieves attributes for a specific attribute group from the Profiles Store |
| `get_attribute_group`    | Retrieves an attribute group from the Profiles Store                        |
| `push_intervention`      | Push an intervention to subscribers for a set of attribute keys             |
| `pull_interventions`     | Open a streaming subscription of interventions for a set of attribute keys  |

### Node.js SDK

Package: [`@snowplow/signals-node`](https://www.npmjs.com/package/@snowplow/signals-node) on npm. The `Signals` constructor takes one options object:

<ParamTable>
  <Param name="baseUrl" type="string" required>
    The Signals API URL.
  </Param>
  <Param name="apiKey" type="string" required>
    The Snowplow API key.
  </Param>
  <Param name="apiKeyId" type="string" required>
    The Snowplow API key ID.
  </Param>
  <Param name="organizationId" type="string" required>
    The Snowplow organization ID.
  </Param>
</ParamTable>

#### Node.js SDK methods

| Method                      | Description                                                                 |
| --------------------------- | --------------------------------------------------------------------------- |
| `getServiceAttributes`      | Retrieves attributes for a specific service from the Profiles Store         |
| `getGroupAttributes`        | Retrieves attributes for a specific attribute group from the Profiles Store |
| `getBatchServiceAttributes` | Retrieves attributes for multiple identifiers from a service                |

[Retrieve attributes](/docs/signals/applications/retrieve-attributes/index.md) documents the arguments for each retrieval method.

## Endpoints

All endpoints are relative to your Signals API URL, shown here as `{{API_URL}}`.

### Signals API endpoints

| Endpoint                | Description                                                                                                    |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| `{{API_URL}}/docs/`     | Swagger documentation for your deployment. Console also links to it from **Overview** > **Configuration details**. |
| `{{API_URL}}/api/v1/...` | The Signals API. Requests need an `Authorization: Bearer <JWT>` header.                                        |

To get the JWT, exchange your API key and key ID at the Console Credentials API, `https://console.snowplowanalytics.com/api/msc/v1/organizations/<ORGANIZATION_ID>/credentials/v3/token`, sending them in the `X-API-Key-ID` and `X-API-Key` headers. The token is valid for 24 hours. See [Connect to Snowplow Signals](/docs/signals/connection/index.md#signals-api) for the commands.

### Signals MCP server endpoint

The [Signals MCP server](/docs/signals/applications/mcp-server/index.md) serves calculated attributes and agentic contexts to an agent in your application as read-only tools. It uses streamable HTTP at:

```bash
{{API_URL}}/mcp
```

It takes the API key and key ID directly, in the `X-API-Key-Id` and `X-API-Key` headers, so there's no token exchange.

## Example

A Python client and a Node.js client created from the same environment variables:

<CodeGroup groupId="signals-sdk">

```python title="Python"
import os
from snowplow_signals import Signals

sp_signals = Signals(
    api_url=os.environ["SIGNALS_API_URL"],
    api_key=os.environ["SNOWPLOW_API_KEY"],
    api_key_id=os.environ["SNOWPLOW_API_KEY_ID"],
    org_id=os.environ["SNOWPLOW_ORG_ID"],
)
```

```typescript title="Node.js"
import { Signals } from '@snowplow/signals-node';

const signals = new Signals({
  baseUrl: process.env.SIGNALS_API_URL,
  apiKey: process.env.SNOWPLOW_API_KEY,
  apiKeyId: process.env.SNOWPLOW_API_KEY_ID,
  organizationId: process.env.SNOWPLOW_ORG_ID,
});
```

</CodeGroup>
